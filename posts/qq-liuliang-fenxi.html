用 Wireshark 看 QQ 流量：它走 TCP 还是 UDP，内容加密了吗

2026-10-18 · 网络 / 抓包 / 原创

平时用 QQ 聊天、传文件，脑子里一直有个好奇：这些字节在网络里到底是怎么跑的？是走 TCP 还是 UDP？内容是不是明文？万一抓到包，能不能把别人传的文件还原出来？趁着手边有 Wireshark，我决定自己抓一份真实流量来验证，而不是凭印象下结论。

一、抓包环境与方法

环境很简单：一台连着 WLAN 的 Windows 电脑，QQ 保持登录并处于活跃状态。先在命令行用 netstat -ano 配合 QQ 进程的 PID，找出它正在连的服务器地址和端口——主要两类：

  • 长连接：到 157.148.x.x:14000（QQ 经典的长连接服务端口）；
  • 业务连接：到一批 27.44.x.x:443、221.11.x.x:443、220.197.x.x:443 等的 443 端口。

把这些地址写进 Wireshark 的捕获过滤器，在 WLAN 网卡上抓了 45 秒，得到 977 个数据包。下面所有结论都来自这份真实抓包，没有"想当然"。

二、问题一：TCP 还是 UDP？

先看传输层分布。这次抓到的 977 个包全部是 TCP，具体拆分大致是：

  • 约 305 帧是 TLS（TLSv1.3 / TLSv1.2 / SSL / TLSv1 混合）——也就是跑在 443 端口上的加密业务流量；
  • 约 225 帧是裸 TCP 载荷（Wireshark 标为 data）——这是 QQ 自己的私有协议，多数走那条 :14000 长连接；
  • 其余是 TCP 握手、确认等协议开销。

把会话（Conversations）按流量排个序，对端清一色是腾讯机房地址，端口集中在 443 和 14000：

对端（已脱敏）端口协议包数字节
27.44.123.x443TLS~91~6.8 KB
27.44.121.x443TLS~94~11 KB
221.11.190.x443TLS~53~8 KB
220.197.31.x443TLS~40~22 KB
157.148.54.x14000私有协议长连接—

结论：QQ 的数据面以 TCP 为主——消息和文件传输走 TCP 上的 TLS（443）或私有协议（14000）。那 UDP 呢？在这 45 秒窗口里没抓到 UDP 包，但用 netstat 在同一台机器上确实看到过 QQ 的 UDP 连接（例如到 27.44.120.x:443 的 UDP）。所以更准确的说法是：TCP 和 UDP 都用，但承载消息/文件的是 TCP，UDP 更多出现在心跳、部分推送类场景。

三、问题二：加密还是明文？

这是最关键的。判断方法很简单：把一段载荷单独拎出来，看它像不像可读文本，再算一下信息熵——明文文本熵很低（英文字母、空格分布集中），而加密/压缩后的字节熵会非常接近理论最大值 8 bit/byte（完全随机）。

对这份抓包实测：

载荷类型样本字节信息熵判定
裸 TCP 私有协议29,2397.955 / 8≈随机 → 加密
TLS 应用数据49,9377.997 / 8≈随机 → 加密

两类载荷的熵都几乎顶到 8，和"随机数"没区别。再直观点：在 Wireshark 里 Follow 任意一条 TCP 流，满屏都是不可读的十六进制，看不到任何聊天内容、账号或明文 XML/JSON。

结论：QQ 通信全程加密。443 端口走标准 TLS，14000 长连接走私有加密协议，两者对抓包者来说都是密文。

四、问题三：能从抓包里恢复明文传输的文件吗？

既然要传文件，自然会想：能不能像"按文件头特征拼回文件"那样，从流量里把别人发的图片、压缩包还原出来？做法是：在原始载荷里按常见文件头做特征搜索——

  • JPEG → FF D8 FF
  • PNG → 89 50 4E 47
  • ZIP/RAR → 50 4B 03 04 / 52 61 72 21
  • PDF、GIF、MP3 等也各有一组固定头。

在这份抓包里挨个搜了一遍，命中数为 0。原因很直接：文件本身是被加密隧道包裹着传的，落到抓包里的已经是密文，文件头的那几个"特征字节"早就被加密打乱了，自然搜不到。

顺带看了一下"在线传输方式"：本次抓到的文件/消息类会话，对端全部是腾讯机房 IP（:443 那一堆），没有看到本机直连对端真实地址的 P2P 痕迹——说明走的是服务器中转。这也解释了为什么抓到的全是到腾讯服务器的加密流。

结论：在 QQ 当前这种全加密的前提下，无法从抓包恢复出明文文件。而"搜不到文件头"这个失败本身，恰好就是"它加密了"的最有力证据。

五、PC 与手机端的一点对照

把手机也连到同一网络出口后抓包，流量特征与 PC 端一致：同样是到腾讯服务器群的 TCP/TLS 加密流，同样看不到明文。换句话说，端到端加密不是某一端的事，而是整套服务的默认行为。

六、小结

想搞清楚的问题实测答案
走 TCP 还是 UDP？都用；数据面以 TCP 为主（TLS 443 + 私有协议 14000），UDP 多见于心跳/推送
加密还是明文？全程加密（裸 TCP 私有协议熵 7.955/8，TLS 应用数据熵 7.997/8）
能恢复明文文件吗？不能；文件在加密隧道内，按文件头特征搜索 0 命中，走服务器中转
一次真实的抓包，比十句"听说"都管用。网络协议这种东西，自己抓一份、对着字节算一遍熵，很多模糊的印象就变成确定的结论了。
