算法入门：它到底是什么，又该怎么衡量

2026-09-28 原创算法

很多人一听到"算法"就觉得高深，其实它离生活很近。本文想把这层神秘感拆掉：先说清算法到底是什么，再说怎么判断一个算法"好不好"，最后用两个小例子体会不同解法之间的差距。

一、算法就是"做一件事的步骤"

算法（Algorithm）本质上是一组明确、有限、可重复执行的步骤，用来把某个输入变成期望的输出。它不局限于计算机——你早上冲一杯咖啡的流程，就是一套算法：烧水、研磨、注水、等待……每一步都清楚，顺序也对，最终结果稳定。

放到编程里，算法解决的是"给定一个问题时，计算机该按什么步骤算"这件事。同一个问题常常有多种算法，区别就在快慢和占多少内存。

二、好算法的三个标准

  • 正确性：对，能给出正确答案，边界情况也不崩。
  • 可读性：人能看懂、好维护。炫技但没人能改的代码不是好算法。
  • 效率：也就是时间和空间开销——这恰恰是衡量算法好坏最核心、也最容易拉开差距的地方。

三、怎么衡量效率：时间复杂度与大 O

我们没法用"跑了几秒"来衡量效率——因为机器快慢、数据大小都会影响结果。真正公平的办法是看随着输入规模 n 增大，操作次数怎么增长，这就是时间复杂度，通常用大 O 表示法描述最坏情况下的增长趋势。

几个最常见的量级（从上到下越来越快）：

  • O(n²)：两层循环，n 翻倍操作数约变 4 倍；
  • O(n)：扫一遍，随 n 线性增长；
  • O(log n)：每次砍掉一半，数据翻很多倍也只多几步；
  • O(1)：无论数据多大，一步到位。
大 O 看的是"增长趋势"而非精确次数，所以它帮我们忽略常数差异、抓住主要矛盾：当 n 很大时，O(n) 一定远胜 O(n²)。

四、例子一：两数之和

问题：给一个整数数组和一个目标值，找出和为目标值的两个数的下标。比如 nums = [2, 7, 11, 15]，target = 9，答案应是 [0, 1]。

解法 A：暴力枚举

把每两个数都配一遍，看和是否等于目标。两层循环，时间复杂度 O(n²)。

def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
  for j in range(i + 1, n):
      if nums[i] + nums[j] == target:
          return [i, j]
    return []

解法 B：哈希表

边遍历边把"数值 → 下标"记进哈希表；每次只看"还差多少"（target - 当前数）是否已经出现过。只扫一遍，时间复杂度 O(n)。

def two_sum_hash(nums, target):
    seen = {}
    for i, x in enumerate(nums):
  if target - x in seen:
      return [seen[target - x], i]
  seen[x] = i
    return []

同样是正确答案，数据量从几千涨到几万时，O(n²) 的解会慢成百上千倍，而 O(n) 的解几乎不受影响——这就是算法"好坏"的直观差距。

五、例子二：二分查找

问题：在一个已排好序的数组里找某个数。最笨的做法是从头扫到尾，O(n)。但既然有序，我们可以每次都和中间的数比：比目标大就扔掉右半边，比目标小就扔掉左半边，不断把范围砍半。这就是二分查找，时间复杂度 O(log n)。

def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
  mid = (lo + hi) // 2
  if nums[mid] == target:
      return mid
  if nums[mid] < target:
      lo = mid + 1
  else:
      hi = mid - 1
    return -1

10 亿个数里找一个数，线性查找最坏要 10 亿步，二分查找只要约 30 步（因为 2³⁰ ≈ 10 亿）。这就是 O(log n) 的威力。

六、小结

算法不是玄学，它只是"把事情做对的步骤"。判断一个算法好不好，最实用的标尺是时间复杂度：先想清楚它随数据量怎么增长，再决定要不要用。入门阶段不必死记所有算法，先把"同一问题能有多种解法、解法之间效率天差地别"这件事刻进直觉，后面学排序、图、动态规划就会顺很多。
